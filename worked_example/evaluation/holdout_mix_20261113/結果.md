# 軽い方式のタヌキが低い理由（2026-11-13 に確かめた。gold は使っていない）

利用者の「確かめる」（「タヌキが低い理由を、gold を使わずに確かめますか？」への答え）を受けて調べた記録です。数字は、このフォルダの台本の出力から make_report.py が入れています。

## 分かったこと

1. **原因は、軽い方式が答えを出すときに、元の SpeciesNet の確率を 3 割混ぜること（学習の窓の設定「元のモデルを混ぜる割合」= 0.3。train_base_mix）です。** 同じ分類器で、混ぜる割合だけを 0 にすると、学習に使っていない動画（検証用の地点の動画）でのタヌキの正解率は、1 回目の材料で 87.2% → 94.9%（39 本）、2 回目の材料で 78.9% → 90.6%（128 本）、3 回目の材料で 79.3% → 95.5%（242 本）に上がりました。
2. **仕組み：** 元の SpeciesNet は、タヌキの枠に、タヌキの確率をほとんど付けません（3 回目の材料の検証用の動画で、枠ごとの確率の中央値 0.03）。3 割混ぜると、新しい分類器がタヌキに 1.0 を付けた枠でも、タヌキの確率は 0.7 あまりにしかなりません（中央値 0.71）。アプリは、第 1 種を「確率が 0.5 以上の枠のうち、確率の高い 3 枚の平均がいちばん高い種」に決めます（設定「第 1 種の決め方」species_pick = confidence）。そのため、ほかの種（アライグマ、アナグマ、イノシシなど）に高い確率が付いた枠が 1〜2 枚あると、タヌキの枠のほうがずっと多くても、その種が第 1 種になります。
3. **混ぜるのをやめると、下がるものもあります。** 検証用の動画では、動物なしが −3.37、−4.90、−4.53 ポイント（1・2・3 回目の材料）でした。3 回目の材料では、アライグマが −2.96（−4.91〜−1.18）、ネコが −2.01（−3.83〜−0.42） でした。動物全体では +0.93、+0.59、+1.07 ポイント、動物なしを合わせた合計では +0.32、−0.05、+0.52 ポイントで、合計はほとんど変わりません。
4. **gold では、混ぜる割合を変えた計算はしていません。** 混ぜるのをやめたときに、gold のタヌキが方式 B（93〜97%）と同じところまで上がるかは、まだ分かりません。

## 調べ方

- **使った動画：** アプリが学習のときに「検証用」に取り分ける地点の動画です（地点の 2 割。設定は既定のまま、乱数の種も同じ）。この動画は、ここで使った分類器の学習に入っていません。gold の 3 つのプロジェクトは開いていません。
- **使った分類器：** 検証用の地点を除いて学習した分類器です。アプリの学習の関数（trapnote.train の collect_all と _run_train_a）をそのまま呼んで作りました。アプリが学習の途中で検証に使うものと同じです。
- **変えたもの：** 答えを出すときの「元のモデルを混ぜる割合」だけです（0.3・0.2・0.1・0）。分類器、動画、枠、第 1 種の決め方（p1 = 0.5 など）は同じです。
- **数え方：** gold の集計（compare_gold.py）と同じ関数で数えました。対象は、人の判定に「不明」がなく、人の判定の種が全部モデルの選択肢（17 種類）に入る動画です。正解は、第 1 種が人の判定に含まれることです。
- **差の幅：** 地点を単位にした並べ直し 20,000 回の 95% の幅です。地点は、材料に加えたプロジェクトの名前を外した名前で数えました。
- **元のプロジェクトには書き込んでいません。** プロジェクトの小さなファイルとデータベースの写しを一時フォルダに作り、アプリの Project でその写しを開きました。特徴量だけは、元の場所から読みました（読むだけ）。調べる前とあとで、6 つのプロジェクトのデータベース（更新の時刻と大きさ）、確認済みの本数、特徴量の数、処理の記録は同じでした。

- 第 1 種になった種の枠では、新しい分類器も元の SpeciesNet も、その種に高い確率を付けていました（3 回目の材料で、枠の最大の平均が 0.96 と 0.84）。その種が 0.5 以上になった枠は、40 本のうち 28 本で 1〜2 枚でした。新しい分類器が少ない枚数だけ間違えた枠に、元の SpeciesNet の誤りが重なった形です。
- 確かめ：混ぜたまま（0.3）で、第 1 種の決め方だけを「0.5 以上の枠の枚数がいちばん多い種」（species_pick = count）に変えると、タヌキの正解は 37 本（1 回目の材料。混ぜないときは 37 本）、115 本（2 回目の材料。混ぜないときは 116 本）、231 本（3 回目の材料。混ぜないときは 231 本）になりました。混ぜないときとほぼ同じです。原因は、「3 割混ぜること」と「上位 3 枚の平均で決めること」の組み合わせです。これは仕組みの確かめで、決め方を変える提案ではありません（決め方は、SpeciesNet と方式 B の評価にも使っている規則です）。

## 言えること、言えないこと

- 言えること：軽い方式のタヌキが低いのは、元の SpeciesNet の確率を 3 割混ぜるためです。学習に使っていない動画で、混ぜる割合だけを変えて確かめました（3 回目の材料で +16.12（+11.36〜+20.95）、2 回目の材料で +11.72（+6.02〜+17.83））。
- 言えること：混ぜることには、よい面もあります。動物なしと、元の SpeciesNet が得意な種（アライグマ、ネコ）は、混ぜたほうが高くなりました。動物なしを合わせた合計では、混ぜても混ぜなくても、ほとんど同じです。
- 言えないこと：混ぜるのをやめたときに、gold のタヌキがどこまで上がるかは、分かりません。gold では計算していません（gold を見て設定を決めないためです）。
- 言えないこと：検証用の地点は「知らない地点」ではありません。アプリは、材料に加えたプロジェクトの地点を別の地点として分けるので、検証用の地点と同じ名前の地点が、別のプロジェクトの動画として学習に入っています（1 回目の材料で 67 地点のうち 56 地点、2 回目の材料で 119 地点のうち 119 地点、3 回目の材料で 141 地点のうち 141 地点。1 回目の材料で加えたプロジェクトは、Empty_2000 だけです）。正解率の高さそのものは、知らない地点より甘い数字です。混ぜる・混ぜないの比較は、同じ動画どうしの比較なので、この点には左右されません。
- 言えないこと：混ぜる割合をいくつにするのがよいかは、ここでは決めていません。タヌキを取るか、動物なしを取るかの選び方になるので、利用者が決めることです。

## 気づいたこと（アプリの検証の記録について。プログラムは変えていない）

- 学習の記録（model.json の eval）の「種ごとの表」で、人の判定の種が 2 つ以上ある動画がどの種の行に数えられるかは、TrapNote を起動するたびに変わることがあります（集合の並び順で決めているため）。本数の合計、一致の数、第 1 種の正解の数は変わりません。変わるのは、種ごとの行の内訳だけです。
- 検証用の地点は、プロジェクトごとに別の地点として分けられます（上の「言えないこと」）。学習の窓に出る「検証用の一致率」は、ほかのプロジェクトを材料に加えたときは、知らない地点での値ではありません。
